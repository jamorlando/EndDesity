# 团队工作日志与智能复盘管理系统 —— 项目开发规范与工程要求说明书

## 1 规范概述与适用范围
本文档为本系统的**代码编写、分层设计、接口通信、安全防御、异常处理、全栈命名规范及 AI 协同开发**的统一规范准则。  
本系统所有后端（Python + FastAPI）与前端（Vue 3 + Vite）代码的编写，均须无条件遵守本文档所列技术条规。

## 2 后端工程规范 (Python 3.11+ & FastAPI)

### 2.1 架构组织模式：按功能模块高内聚切片（Package by Feature）
系统摒弃散乱的扁平分层，全面采用**按业务功能垂直切片（一个功能一个文件夹）**的组织模式：
```text
backend/app/
├── core/                     # 【全局底座】数据库会话、安全加密、统一响应、全局配置
│   ├── config.py             # 读取 .env 的配置类
│   ├── database.py           # 数据库异步引擎与会话工厂 (SQLAlchemy 2.0)
│   ├── security.py           # BCrypt 密码加密与 PyJWT 签名工具
│   ├── response.py           # 统一 JSON 响应体结构包装
│   └── exceptions.py         # 自定义业务异常与全局错误拦截器
│
├── modules/                  # ⭐【功能模块区：一个功能一个独立文件夹！】
│   ├── auth/                 # 1. 用户账号与认证 (登录、注册、修改密码、防暴破锁定)
│   │   ├── models.py         # users, password_histories 实体模型
│   │   ├── schemas.py        # 登录入参、Token出参等 Pydantic 校验
│   │   ├── service.py        # 认证业务逻辑、密码历史防重校验
│   │   └── router.py         # /api/v1/auth 路由入口
│   │
│   ├── teams/                # 2. 团队与组织架构 (团队CRUD、组员审核、标签字典)
│   ├── projects/             # 3. 跨组项目与工作日历 (项目生命周期、节假日排班)
│   ├── work_logs/            # 4. 工作日志核心 (动态JSON表单、版本快照、附件、评论)
│   ├── retrospective/        # 5. 智能复盘引擎 (KISS/GRAI模型、AI长文本切片、ActionItems)
│   └── stats/                # 6. 效能大屏与审计 (每日聚合快照预计算、ECharts看板、安全审计)
│
├── integrations/             # 【第三方可插拔适配器】
│   ├── ai/                   # 大模型统一网关 (DeepSeek, Qwen, Ollama, Mock沙箱)
│   └── wechat/               # 企业微信推送适配器 (Agent API & 群机器人 Webhook)
│
├── utils/                    # 通用独立工具库 (puremagic文件魔数嗅探、Word公文生成)
└── main.py                   # FastAPI 应用启动入口 (中间件加载与模块路由汇总)
```
* **【职责红线】**：
  - `router.py` 只负责接收 HTTP 请求、校验入参、调用 service，**严禁在 router 中直接写 SQL 或 ORM 查询**；
  - `service.py` 承载全部事务与业务逻辑，跨模块调用必须调用对方的 service，禁止直接跨模块操作私有模型；
  - `models.py` 纯净映射数据库表结构，禁止包含 HTTP 或展示层逻辑。

### 2.2 Python 语法与类型约束
1. **类型提示（Type Hints）100% 覆盖**：所有函数必须显式声明入参类型与返回值类型（无返回值显式声明 `-> None`）。
   ```python
   # 正确示范
   async def get_team_by_id(session: AsyncSession, team_id: int) -> Optional[Team]:
       ...
   ```
2. **全面采用 SQLAlchemy 2.0 异步语法**：
   - 严禁使用已废弃的 1.x 语法（如 `session.query(User).filter(...)`）；
   - 必须使用标准 2.0 语法：`select(User).where(User.team_id == team_id)` 配合 `await session.execute(...)`。
3. **Pydantic V2 严格验证**：
   - 入参统一继承 `BaseModel`；
   - ORM 对象反序列化必须声明 `model_config = ConfigDict(from_attributes=True)`。

## 3 前端工程规范 (Vue 3 + Vite + Element Plus)

### 3.1 组件化与现代 API 规范
1. **统一采用 `<script setup>` 语法糖与 Composition API**，严禁混用 Options API。
2. **单文件行数控制**：单个 `.vue` 组件文件代码量**严禁超过 350 行**。超长页面必须按视觉区块拆分子组件（如 `components/RetroKanbanColumn.vue`）。
3. **单文件结构顺序统一**：
   ```html
   <template> ... </template>
   <script setup> ... </script>
   <style scoped> ... </style>
   ```
4. **状态管理规范**：
   - 跨页面共享数据（当前登录用户、Token、权限菜单、未读红点）必须存入 **Pinia Store**；
   - 页面内部瞬态采用 `ref()` / `reactive()` 局部管理，严禁污染全局状态。

### 3.2 UI 交互体验规范
1. **异步交互三部曲**：所有耗时操作必须包含：
   - 视觉加载态（`v-loading` 或骨架屏）；
   - 成功反馈（`ElMessage.success`）；
   - 失败兜底（友好中文 `ElMessage.error`，严禁静默失效）。

## 4 API 接口设计与网络通信契约

### 4.1 RESTful 路由风格规范
1. 统一遵循小写、中划线（kebab-case）与复数名词规则；
2. 基础路由前缀统一为 `/api/v1`：
   - 获取指定团队日志列表：`GET /api/v1/teams/{team_id}/work-logs`
   - 提交个人日志：`POST /api/v1/work-logs`
   - 触发智能复盘：`POST /api/v1/retrospectives/generate`

### 4.2 统一统一标准响应结构体 (Standard Response)
所有接口无论成功或失败，后端均返回统一 JSON 结构，前端 Axios 响应拦截器统一解包：
```json
{
  "code": 200,
  "message": "success",
  "data": { ... },
  "timestamp": 1773289000
}
```
* **业务状态码约定**：
  - `200`：操作成功；
  - `400`：客户端参数校验不通过；
  - `401`：未登录或 Token 失效过期；
  - `403`：权限不足（如组员尝试访问系统全量审计）；
  - `404`：资源不存在；
  - `500`：服务器内部受控异常（返回友好提示，详细日志留痕）。

## 5 安全加固与敏感数据防线

1. **环境凭据隔离**：
   - 数据库连接串、JWT 密钥、大模型 API Key 必须存放于根目录 `.env` 文件；
   - `.env` 必须写入 `.gitignore`，**严禁将包含明文密码的文件提交至 Git 仓库**；
   - 代码中通过 `pydantic-settings` 强类型安全加载。
2. **附件安全防御**：
   - 严禁仅信赖客户端传来的扩展名，必须使用 `puremagic` 库嗅探**二进制文件头（Magic Bytes）**；
   - 文件物理落盘一律采用 `UUID4` 重命名，彻底杜绝同名覆盖与路径穿越（Path Traversal）漏洞。
3. **数据查询安全（防 SQL 注入与越权）**：
   - 严禁使用 Python 字符串拼接构造 SQL；
   - 主管与组员接口在后端强制注入 `current_user.team_id` 进行行级隔离，杜绝横向越权。

## 6 异常处理与系统审计日志规范

1. **自定义业务异常体系**：
   - 后端建立统一业务异常基类 `AppException(HTTPException)`；
   - 细化子类：`ResourceNotFoundError`, `PermissionDeniedError`, `BusinessValidationError`。
2. **堆栈遮蔽原则**：
   - 生产环境中全局异常处理器（Global Exception Handler）拦截所有未捕获异常；
   - 日志记录完整的 Traceback，向前端仅输出“系统繁忙，请稍后重试”，绝对禁止将 SQL 报错直接显示在浏览器。

## 8 新时代 AI 协同开发守则

在使用 AI 智能体辅助生成代码时，必须遵循以下步骤：

1. **先对齐契约再写逻辑**：
   - 让 AI 生成任何业务接口前，必须先在 Prompt 中指定其阅读本文档以及《数据库设计说明书》中对应的表定义；
2. **单次原子化聚焦**：
   - 每次只给 AI 指派一个独立切片（如：“完成 `modules/auth` 的密码加盐哈希与登录 Token 生成”）；
3. **验证闭环再推进**：
   - 代码生成后，立刻运行 `ruff check .` 检查语法和格式，验证通过后再进行下一模块；
4. **Git 检查点留痕（Conventional Commits）**：
   - `feat:` 新增业务功能
   - `fix:` 修复缺陷
   - `refactor:` 代码重构（不改变外部行为）
   - `docs:` 文档变更
   - `test:` 补充单元测试

## 9 Agentic DevOps 与智能体工具 (Agent Tools / MCP) 架构扩展规范

### 9.1 架构设计理念：走向第二代自主智能研发协同中台
传统研发协作系统的核心痛点是**"被动填报（Passive CRUD）"**，导致一线工程师存在填报抵触，复盘动作与实际代码变更割裂。  
本系统确立**"人类交互前台（Web Console） + 智能体能力插件（Agent Tools / MCP Server）"**双轮驱动架构，将系统核心能力沉淀为可被外部智能体（如 Cursor、Claude Code、Antigravity、自主 PM Agent）调用的原子化工具集，实现：
1. **代码提交自动感知填报**：Coding Agent 读取开发者当天的本地 Git Commit 与 PR 提交，自动调用日志工具入库；
2. **敏捷复盘智能调度下发**：PM Agent 周期性调用复盘与行动项工具，自主提炼 KISS 矩阵并向组员派发改进项；
3. **管理层自然语言效能探针**：CTO Agent 通过对话实时查询团队技术卡点与交付燃尽态势。

### 9.5 系统内置 ReAct 智能体认知循环引擎

后端 `app/modules/agent/` 模块实现**完整的 ReAct（Reasoning + Acting）认知循环**：

```text
用户输入 (自然语言)
    │
    ▼
[Thought]     大模型解析用户意图，决定调用哪个 Tool
    │
    ▼
[Action]      后端执行对应 Tool（携带行级权限校验 + 团队隔离）
    │
    ▼
[Observation] 工具返回结构化数据，反馈给大模型
    │
    ▼
[Response]    大模型组织最终自然语言回复 + 结构化卡片
    │
    ▼  (SSE 流式实时打字机输出至前端)
```

**引擎关键特性**：
- **最大步数熔断保护**：单次对话最多执行 **5 轮**工具调用，防止死循环；
- **离线 Mock 沙箱保活**：当 `LLM_PROVIDER=mock` 或网络不通时，自动无感降级至本地高仿真决策树，答辩演示 100% 稳定；
- **多角色 System Prompt 模板**：三大角色各自持有独立的 System Prompt（`prompts.py`），固化 KISS 规范、输出格式约束与安全操作红线。

**模块目录落位**：
```text
backend/app/modules/
├── agent_tools/            # 工具契约层（已有）
│   ├── schemas.py          # 6大工具的 Pydantic V2 入参/出参 + MCP JSON Schema 声明
│   ├── service.py          # 工具执行实现（调用 work_logs/retrospective/stats 服务）
│   └── router.py           # GET /api/v1/agent-tools/manifest  |  POST /api/v1/agent-tools/invoke
│
└── agent/                  # 智能体认知中枢（新增）
    ├── prompts.py          # 三大角色 System Prompt 模板（KISS 管理学规范固化）
    ├── service.py          # ReAct 循环驱动引擎 + 离线 Mock 沙箱策略
    └── router.py           # POST /api/v1/agent/chat（SSE 流式 + JSON 双模式）
```

### 9.6 MCP Server 封装规范（对外标准协议暴露）

#### 9.6.1 MCP Server 落地文件

本系统在 backend 目录提供独立 MCP Server 入口，使整个系统可作为标准 MCP 插件被 Cursor、Claude Desktop、Antigravity 等宿主直接发现并调用：

```text
backend/
└── mcp_server.py   # [NEW] MCP Server 标准入口（基于 FastMCP，支持 stdio + HTTP SSE 两种传输模式）
```

#### 9.6.2 MCP Server 实现规范

- 每个 `@mcp.tool()` 装饰器对应一条 Agent Tool 原语，底层**直接复用 `AgentToolsService` 对应的 `_execute_xxx` 方法**，无重复实现；
- 工具描述（docstring）与参数类型注解**自动转换**为标准 MCP JSON Schema，无需手动维护双份声明；
- 支持两种传输模式：
  - **stdio 模式**：用于本地 Cursor / Claude Desktop 集成（`python backend/mcp_server.py`）；

### 9.8 智能体工具执行安全与防护红线 (Security & Guardrails)

1. **统一鉴权与令牌隔离**：
   - 智能体调用 Tool 时必须在 HTTP Header 注入专用应用令牌（`Authorization: Bearer <agent_token>`）；
   - MCP Server 模式下通过环境变量 `AGENT_TOKEN` 注入，严禁硬编码至代码或配置文件；
2. **行级数据隔离（Row-Level Security）严格继承**：
   - 智能体工具后端执行逻辑必须复用底层 Service 层的 `current_user.team_id` 过滤，**严禁智能体越权读写非授权团队的敏感日志与业务数据**；
3. **幂等性与防重复调用保障**：
   - 日志提交工具支持 `idempotency_key`（基于 `user_id + log_date + hash(commit_ids)`），杜绝网络重试引发重复插入；
4. **高危动作"人在回路（Human-in-the-loop）"确认**：
   - 涉及归档团队、批量改密、解散项目等破坏性操作，Tool 返回 `PENDING_CONFIRMATION` 状态，必须由主管在前台点击二次确认方可生效；
5. **ReAct 循环熔断保护**：
   - 单次对话智能体工具调用上限为 **5 次**，超限强制中断并返回提示，防止无限循环消耗 Token 与系统资源。

### 10.2 MCP Server 文件结构规范

MCP Server 落地于 `backend/mcp_server.py`，**独立于 FastAPI 主进程之外单独运行**，与主应用共享 ORM 模型与 Service 层代码：

```text
backend/
├── app/                         # FastAPI 主应用（不变）
│   └── modules/
│       └── agent_tools/
│           ├── schemas.py       # Tool 入参 Pydantic 模型（MCP Server 复用）
│           └── service.py       # Tool 执行实现（MCP Server 复用）

└── requirements.txt             # 追加 mcp[cli] 依赖
```

**职责红线**：
- `mcp_server.py` **只负责**：初始化 FastMCP 实例、注册 `@mcp.tool()` 装饰器、启动传输层；
- **严禁**在 `mcp_server.py` 中直接写 SQL 或 ORM 查询，所有业务逻辑必须调用 `AgentToolsService`；
- `mcp_server.py` 与 `main.py`（FastAPI）相互独立，互不依赖，分别启动。

```python
async def _get_agent_user(db):

    from app.models.org import User
```

### 10.7 工具变更同步规范（单一真相原则）

当业务需要新增或修改工具时，**必须按以下顺序同步三处**，确保 REST API、内置 Agent 与 MCP 三端始终一致：

```
1. agent_tools/schemas.py   ← 先更新 Pydantic 入参/出参模型
        ↓
2. agent_tools/service.py   ← 实现工具底层业务逻辑
        ↓
3. mcp_server.py            ← 注册对应 @mcp.tool() 装饰器（复用 service，只加壳）
```

**严禁**只改其中一处而遗漏其他两处，导致 REST invoke 接口与 MCP 工具能力不一致。
